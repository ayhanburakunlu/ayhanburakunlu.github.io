2025 to present · Built and running in production

An SEO content factory that runs itself, with a human at the gate

Eight agents that take a keyword opportunity through research, briefing, drafting, an adversarial quality review and a human approval step, then publish and monitor it. Two sites run on the same engine today.

n8n (self hosted) · Supabase Postgres · Search Console to BigQuery · DataForSEO · Anthropic Claude Sonnet 5 and Opus 5 · GitHub PR approval · Vercel · Telegram alerts

StageAgentWhat it doesBrainNodes

∞Watchdog Daily health check on the API, the queue and stalled work. Silent on a good day Deterministic7

Green is running daily today. Amber is built and parked until there is enough published content to make it earn its keep. 150 nodes across the eight, part of a live n8n instance carrying 26 workflows.

Spend gate. Every paid call checks the monthly ceiling first and halts rather than overspending. Articles land at roughly $1 to $3 each against a $120 monthly cap.
Link resolution gate. Added after the model invented 46 internal links that did not exist. Now every link is resolved against the real site inventory before the pull request opens.
Transient immunity. Added after an API credit outage silently poisoned the queue. Temporary failures no longer count against a piece of work the way a genuine quality failure does.
Penalty guard. A shared constraint block injected into every writing role, written against Google's scaled content abuse policy. The point was never volume.
Why build it
Every page worth publishing needed roughly half a day of research before anyone could write a word. Keyword and SERP work, competitor gaps, entity and internal link planning. Necessary, repeatable, and a poor use of a specialist.
The design call
It is deliberately not fully autonomous. Publication requires a person to merge a pull request after looking at a live preview. On medical content that is not a nicety, it is the difference between a system you can defend and one you cannot.
What it proved
The engine is one brain with a config file per site, so a second tenant in a different country and a different language was a configuration exercise rather than a rebuild. Most of the hardening in it came from real incidents, not from planning.

How I work

Four things I keep coming back to, all of them learned the expensive way.

Measurement before spend

I have inherited too many accounts where conversion tracking had been quietly broken for months and every decision above it was built on nothing. Tracking gets fixed first, always, even when it delays the launch.

The lever moved to creative

Broad match, smart bidding and Performance Max took the manual levers away, and signal loss blunted targeting on top of that. What is left that genuinely moves cost per acquisition is the creative and the page, so that is where I spend my time.

Build the guardrail after the incident

Almost every guard in my agent system exists because something broke first. Invented links, a credit outage, a silent stall. An automation you cannot observe is a liability, so the alert and the spend ceiling ship with it.

Read the recordings

Most conversion rate arguments end the moment someone actually watches ten people fail to complete the form. Heatmaps and session recordings settle in an afternoon what opinion can argue about for a quarter.
